# Social Copilot Uses Persisted Drafts and Transport-Agnostic Tools

The Social Copilot will operate on persisted draft `socialPosts` rows and reference media-pool assets, rather than mutating ephemeral composer form state. Its capabilities are implemented as a transport-agnostic tool layer — pure service functions wrapped as Vercel AI SDK tools, each receiving an injected `{ workspaceId, userId }` context rather than reading the request session directly. The in-app copilot route supplies that context from the Better Auth session; a future MCP server supplies it from an API key. We chose this over a composer-bound, client-applied-operations model (which mirrors the existing node-editor chat) because the same tools must later serve external agents over MCP, and an MCP client has no composer to apply operations to. The trade-off is that every drafting step writes to the database, so drafts need cleanup and the UI reflects server draft state instead of local form state. Commit actions (`scheduleDraft`, `publishNow`) re-run Publish Validation server-side and require explicit in-chat approval via the AI SDK `needsApproval` gate; see [0002](0002-layer-social-publish-validation.md) and [0006](0006-use-postiz-as-social-parity-reference-not-architecture-template.md).
