## Findings considered and rejected (do not re-audit)

- **Ingest fetch timeout "leak"** (`assets/ingest/route.ts:120-160`): by design — the code comment states the timeout deliberately stays active during stream consumption to enforce an overall deadline.
- **`regenerateNode` leaves `isRunning` stuck true** (`workflowStore.ts:1283-1370`): false — every early-return branch and the catch block reset `isRunning`; what remains is 7× duplicated cleanup (cosmetic; fold into any future refactor).
- **presign-multipart complete/abort IDOR**: false — `finalizeAssetUpload` filters by `workspaceId` in the repository layer; cross-workspace IDs 404. (Auditor self-retracted; confirmed.)
- **`regenerateNode` double-execution race with `executeWorkflow`**: theoretical — the `isRunning` check-and-set is synchronous in Zustand; no await between check and set.
- **Auto-save stale closure** (`workflowStore.ts:2108-2124`): the callback calls `get()` fresh each tick; existing catch paths reset `isSaving`. Mitigated; not worth a plan.
- **Mass assignment via prompts PATCH extra fields**: `updatePrompt` only maps the four declared keys; no current exposure. (Validation still added in plan 005 for defense-in-depth.)
- **API-route IDOR generally**: clean — `authorizeStudioRequest` resolves `x-workspace-id` against the user's own memberships and repository queries filter by `workspaceId`. The authz layering for API routes is sound.
